WebAuthn UI probe

Which request shapes make Chrome show the QR picker, and which go straight to the key. Register once, then try each case and watch what Chrome does.

0a. Register on the SECURITY KEY (our vault)

Sets authenticatorAttachment: "cross-platform", which rules out Chrome's own built-in passkey store and forces the request to our virtual key. Touch the sensor when asked.

0b. Register with no constraint

What most sites do. Shows which provider Chrome picks when left to choose. Watch the reported transports: ["usb"] is our key, ["hybrid","internal"] is Chrome's own store.

1. Discoverable request (empty allowCredentials)

What webauthn.io's Authenticate button does. Chrome cannot know where the passkey lives, so it must offer every transport including a phone.

2. Targeted, transports: ["usb"]

Names the credential and says it is on a USB device. Chrome has enough to skip the phone option.

3. Targeted, no transport hint

Names the credential but says nothing about where it is.

4. Discoverable + hints: ["security-key"]

WebAuthn L3 hints, which asks Chrome to prioritise a security key without naming a credential.
